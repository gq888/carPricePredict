# 车辆价格预测模型 - 增强版Baseline

## 项目概述

本项目是对原有车辆价格预测baseline的增强实现，采用了模块化设计，包含四个核心阶段：数据清洗、探索性数据分析(EDA)、特征工程和数据建模。每个阶段都被封装为独立的闭包函数，实现了完整的缓存机制和依赖检查。

## 主要特性

### 1. 模块化架构
- **数据清洗阶段**: 处理缺失值、异常值检测、数据类型检查
- **探索性数据分析阶段**: 目标变量分析、特征统计分析、相关性分析、可视化
- **特征工程阶段**: 特征选择、特征构造、分类变量编码、特征标准化
- **数据建模阶段**: 多模型训练、交叉验证、模型比较、预测生成

### 2. 缓存机制
- 每个阶段的输出结果都会缓存到文件系统
- 支持依赖项变更检测，自动重新计算过期缓存
- 缓存文件存储在 `/Users/qingguo/Documents/project/carPricePredict/cache/` 目录

### 3. 依赖管理
- 严格的依赖检查机制，确保阶段执行顺序正确
- 全局变量作为唯一的数据通信方式
- 闭包函数之间不直接相互调用

### 4. 模型多样性
- 实现了逻辑回归和随机森林两种模型
- 使用交叉验证进行模型评估
- 自动选择最佳模型进行最终预测

## 详细功能说明

### 数据清洗阶段 (`data_cleaning_stage`)

**功能子阶段:**
1. 数据加载和基本信息输出
2. 缺失值分析
3. 异常值检测（使用IQR方法）
4. 数据类型检查
5. 负值处理（将负值设为NaN）

**输出缓存:**
- 清洗后的训练数据 (`train_clean`)
- 清洗后的测试数据 (`test_clean`)
- 缺失值统计信息

### 探索性数据分析阶段 (`eda_stage`)

**功能子阶段:**
1. 目标变量分布分析（违约率计算）
2. 数值特征统计分析
3. 类别特征频次分析
4. 特征与目标变量相关性分析
5. 可视化图表生成

**输出缓存:**
- 目标变量分布统计
- 数值特征统计描述
- 相关性分析结果
- 类别特征分析结果
- EDA可视化图表

### 特征工程阶段 (`feature_engineering_stage`)

**功能子阶段:**
1. 特征选择（基于EDA结果）
2. 新特征构造：
   - 还款压力指数 = 月还款额 / (信用评分高值 + 1)
   - 信用评分差值 = 信用评分高值 - 信用评分低值
   - 贷款收入比 = 贷款总额 / (月还款额 * 12 + 1)
3. 分类变量编码（Label Encoding）
4. 缺失值填充（使用中位数）
5. 特征标准化（StandardScaler）

**输出缓存:**
- 特征工程后的训练数据 (`train_fe`)
- 特征工程后的测试数据 (`test_fe`)
- 标准化后的数据 (`train_scaled`, `test_scaled`)
- 特征列名列表
- 标准化器对象

### 数据建模阶段 (`modeling_stage`)

**功能子阶段:**
1. 逻辑回归模型训练
   - 5折交叉验证
   - AUC评分
2. 随机森林模型训练
   - 5折交叉验证
   - AUC评分
3. 模型比较和选择
4. 最佳模型预测
5. 提交文件生成

**输出缓存:**
- 训练好的模型对象
- 交叉验证结果
- 测试集预测结果
- 提交文件路径

## 缓存机制详解

### 缓存结构
每个阶段的缓存包含以下信息：
```python
{
    'data': 阶段输出结果,
    'dependency_hash': 依赖项哈希值,
    'timestamp': 缓存时间戳
}
```

### 依赖检查
系统通过以下步骤检查是否需要重新计算：
1. 计算当前依赖项的哈希值
2. 与缓存中的依赖哈希值比较
3. 如果哈希值不同，则认为依赖项已变更，需要重新计算
4. 如果哈希值相同，则直接使用缓存结果

### 缓存文件命名
- `stage_data_cleaning.pkl`
- `stage_eda.pkl`
- `stage_feature_engineering.pkl`
- `stage_modeling.pkl`

## 错误处理

### 常见错误及解决方案

1. **数据文件缺失**
   - 确保 `data/train.csv` 和 `data/testA.csv` 存在
   - 检查文件路径是否正确

2. **缓存加载失败**
   - 删除缓存目录重新运行
   - 检查磁盘空间是否充足

3. **模型训练失败**
   - 检查数据格式是否正确
   - 确保所有依赖阶段已正确执行
